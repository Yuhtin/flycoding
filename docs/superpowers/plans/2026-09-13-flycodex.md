# Flycodex Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the approved local fly-connectome/Codex pilot, with a reproducible neural probe, working CLI and dashboard, durable limits, tests, and honest results.

**Architecture:** Python coordinates a pinned derived Stonkfly neural core, an independently evaluated discount task, a subprocess Codex adapter, and a read-only local dashboard. Local JSON artifacts form the observable interface; neural activity chooses actions without a language-model selector.

**Tech Stack:** Python 3.11+, NumPy, pandas, PyArrow, Pillow, C++17, pytest, the installed Codex CLI, standard-library HTTP server and HTML/CSS/JavaScript.

**Spec:** `docs/superpowers/specs/2026-09-13-flycodex-design.md`

## Global Constraints

- Network: MaleCNS v1.0, pinned Stonkfly `78ef3e05ab0fa086032098558d893667068944a0`; preserve upstream source and array hashes and license notices.
- Panel: RGB uint8 320 × 180, visible image identical to neural input.
- Actions: Investigate, Fix, Test; use the exact Portuguese prompt strings in the spec.
- Readout: DNp20 mean right minus left, threshold 2 Hz, DNpe017 spike gate. Positive -> Fix, negative -> Test, otherwise -> Investigate, logging the reason.
- Neural decision interval: 500 ms; feedback: 200 ms, positive/negative pulse 20 mV-equivalent, neutral same interval without external pulse; no decisions during feedback.
- Pilot: adaptive, frozen, random; two attempts each, at most five instructions each, 30 total. Frozen weights must remain unchanged. Finish early on success, never reallocate unused budget.
- Feedback: sign of externally evaluated passing-test delta; infrastructure failure is separate.
- Never send real Codex prompts in automated tests. All actual sends, including integration probes, belong to the same persisted 30-send pilot budget. No automatic retry after ambiguous submission.
- Codex: serial turns, explicit session ID, dedicated workspace, 300-second turn deadline, 30-second evaluation deadline, events visibly streamed; no bypass of sandbox/approvals.
- User approved implementation; no additional design or execution permission questions. Implementation stays in this new project; no unrelated local files changed.
- Every shell command must start with `rtk` (use `rtk proxy` for unsupported commands). Use `.venv/bin/python -m pytest` through `rtk proxy`.

### Task 2: Evaluated task, durable budget, and Codex boundary

**Files:** Create `src/flycodex/task.py`, `src/flycodex/storage.py`, `src/flycodex/codex.py`, `tests/test_task.py`, `tests/test_storage.py`, `tests/test_codex.py`.

**Interfaces:**
- `DiscountTask(root: Path)` owns dedicated workspace `root/workspace` and trusted evaluation assets `root/evaluator`; `reset()` creates pristine files; `evaluate() -> dict` yields `passed`, `total`, `tests`, `violation`, `error`. Fixed suite test IDs/results remain identical across attempts.
- `RunStore(root: Path)`: atomic JSON save/load helpers and journal; `reserve(attempt: str) -> str` persists a send ID before submission and enforces 30 global / 5 attempt / 10 condition limits; `complete(send_id: str, result: dict)` closes the reservation once. Pending reservations remain consumed across reopen; unfinished ones never silently resend. Single-writer lock prevents concurrent run processes.
- `CodexRunner(workspace: Path, model: str | None = None, timeout: float = 300, executable: str = "codex")`; `run(prompt: str, session_id: str | None, on_event: Callable) -> dict` returns `session_id`, `status`, `usage`, and `error`. No invisible extra send for initialization. `cancel()` terminates process group and waits. Persist/stream complete JSON events, tolerate non-event diagnostics without masking failed turns.
- `PROMPTS` maps the three lower-case action names to exact spec text. The first turn also receives explicit task context and scoped edit constraints.

- [ ] Write tests that the initial implementation fails known partial/total/rounding cases; correct implementation passes every case; modifying visible tests cannot change external scoring and causes violation; syntax failure is task failure, not evaluator infrastructure success.

- [ ] Write tests for reservation exhaustion across all six attempts, pending reservation counted on reopen, no double completion, and competing writers. - [ ] Write executable fixture processes that emit real-shaped Codex events and either succeed, fail, delay, or omit session ID. Verify actual subprocess arguments, event delivery, resume target and termination; never execute the real Codex in these tests.
- [ ] Implement streaming subprocess transport. Respect saved authentication but select explicit workspace-write sandbox and noninteractive approval failure behavior.
